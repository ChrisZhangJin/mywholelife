<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> API (`/agent/:id/memory`) | Untrusted tar body + scope/project query cross here |
| stored `.tar` -> init `.zip` -> client `unzip` | Entry names flow to a file the client later extracts |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Tampering / Elevation | tar/zip path traversal | mitigate | `safeEntryName` rejects `../`/absolute at ingest (ValidateAndBrief -> 400) AND filters at transcode (copyTarIntoZip); never trust client `unzip`. |
| T-02-05 | DoS | oversized upload / archive bomb | mitigate | `http.MaxBytesReader` (8 MiB) on the body; entry-count + cumulative-byte caps in `ValidateAndBrief`. |
| T-02-06 | Spoofing / Tampering | POST/GET to unknown or forged `{id}` | mitigate | `GetAgent` guard -> 404 on unknown id (no auto-create); FK(agent_id) also blocks orphan writes. Cross-agent overwrite via a forged *known* id is accepted for single-tenant MVP (D-02). |
| T-02-07 | Information Disclosure | init streams another agent's data | accept | Single-tenant, id-as-scope (D-02); List/GetFolder are agent-namespaced by id in the rel_path and query. |
</threat_model>
